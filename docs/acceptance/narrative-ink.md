# Ink 剧情接入记录

日期：2026-10-31（Asia/Shanghai）。本轮按v0.2方案实际落地，保留用户工作区其他改动，复用用户已经启动的dev服务；没有执行启动、重启服务或Docker运行命令。

## 实现范围

- 服务端依赖固定为 `inkjs@2.4.0`。`scenario/ports.ts`定义业务边界，`scenario/runtime/ink.ts`处理解释器、选择、候选checkpoint和投影；`runtime/context.ts`处理角色提示、已公开Lore、历史预算与推荐过滤。
- 咖啡馆内容归入`scenario/cafe/`：manifest、角色、Lore、main、endings和八个地点Ink文件。旧的根级identity/prompt/rules/story分支被迁移，不再用生产正则解释聊天动作。Mock保留明确的离线语义模拟。
- 通过`scenarios:build`编译十个Ink文件并产生带hash/version的compiled.json；`scenarios:check`验证源与产物一致。编译期拒绝EXTERNAL与不支持的tag；runtime使用共享schema校验动作、cue和投影。
- `SessionManager`继续保管会话、代次、回执和存档。候选checkpoint带父存档hash与revision，只有依赖全部满足的实际呈现回执才能原子提交；乱序、冻结与迟到规则继续有效。
- 每个作者beat只有一个主要呈现锚点；必要台词先播放或由用户确认字幕。下游beat等待上一锚点成功，失败或取消不会朗读未公开信件或提交后续结局。部分结局可从已确认前缀改选，不自动续播旧计划。
- Graph正常调用同时生成聊天/合法动作建议和用户候选；严格区分公开ReplyPlan与私有PlannerOutput。关键explicit动作只通过当前合法按钮选择。自然语言动作可以同次附带闲聊候选，全部呈现完成后再显示；纯地图操作不增加LLM调用。
- 候选默认自然接话，探索/决定最多一项，关联ID必须在合法范围内；实际点击推荐仍只填入草稿，确认后按新上下文解释。合法按钮由Ink当前choices驱动，未达到决定节点不展示三结局。
- 道具正文由服务端Lore提供，呈现事件携带已授权的纯文本；前端不再复制信件/回信正文。前端继续负责布局、模型与素材，不接收Ink源码、bytecode或存档JSON。
- 历史使用已有LangChain trimMessages，默认1800估算tokens，无额外网络计数。结构化事实不随裁剪消失；该估算不是用户GPT总context window保证。

## 两个入口

`POST /api/sessions`可选择`entry=story|conversation`，缺省story。WebGAL故事入口从街角开始；原版Vue对话入口在窗边相遇的初始设定中，继续支持照片等原交互，不接收本宿主无法执行的地图操作。两者来自同一Ink包的显式入口与choices，不是第二套剧情引擎。

故事入口天气随离店节点推进，不依赖照片；兼容入口保留照片与雨势的独立演出和回执。旧版本严格客户端需要刷新，当前schemaVersion=3。

## 实际页面调试

使用agent-browser-cli操作现有 `http://localhost:5173/webgal.html` 及原版对话入口。调试页显示当前为Live；通过正常产品入口进行了有界的GPT/Deepgram交互，没有运行provider probe、读取/打印key或录制用户声音。

| 场景               | 实际观察                                                                     |
| ------------------ | ---------------------------------------------------------------------------- |
| 街角进店           | 出现大堂、角色相遇与当前互动；三结局未提前显示                               |
| 走到吧台但未读信   | 只显示署名信封与是否打开的入口，没有将正文计为已读                           |
| 用户要求先聊旅行   | 角色承接旅行话题；出现“聊聊旅行节奏”“说说熟悉的地方”两条候选，未强行推进读信 |
| 明确打开信         | 信纸与正文实际呈现，随后播放她的反应；之后三种决定选项才出现                 |
| 离店到门头时打断   | 保留门头、保持未完成结局，没有提前提交街道与天气                             |
| 打断后改回窗边     | 新导航成功，停留窗边，旧离店计划没有复活                                     |
| 原版聊天页照片联动 | 礼貌请求实际触发照片、独立雨势与闲聊候选；无重复确认                         |

离店打断通过该调试标签页中的一次性MutationObserver，在已呈现的第一段离店旁白出现时触发产品“打断”按钮，观察后即断开；产品源码没有添加该观察器或自动打断功能。

截图在本地 `outputs/ink-implementation/`，不纳入源码仓库；其含义是本轮手动浏览器观察，不是自动测试套件或真机验收。

## 发现并修正的问题

1. Ink选择标签放在方括号外，会进入选择后的输出，currentChoices取不到actionId。已按官方choice tag语法移入方括号内，编译零diagnostic并实际创建会话、导出合法选择。
2. 只比较revision不足以区分分叉后的旧候选。候选增加父存档hash，回执批量提交前一起校验，不盲目加载旧JSON。
3. 旧式模型events可能绕过作者剧情。普通模型计划禁止世界事件与递照片指令，由合法Ink action产生实际演出。
4. 当前聊天和故事入口并存，原聊天宿主不支持地图。引入显式entry初始条件与Ink菜单过滤，复用同一包。
5. 礼貌请求“能看看照片吗”首次被模型当成需要重复确认的询问。补充通用请求语义和故事动作description；不添加生产关键词正则兜底。实际再走查已观察到照片展示与独立雨势变化。

## 检查与边界

已执行并通过：`npm run typecheck`、`npm run lint`、`npm run build`、`contracts:generate / contracts:check`、`scenarios:build / scenarios:check`、`assets:check`、`webgal:check`。Ink十文件零diagnostic；资产检查29条Live2D SHA-256、8基础背景/3变体；WebGAL 304条来源记录/15声明补丁通过。构建保留既有WebGAL大chunk提醒，未将其表述为性能验收。

新增/调整Ink存档、合法动作、未读信息过滤、同次规划、连续前缀、父存档冲突和取消回执等测试代码，**按AGENTS未运行功能、运行时或E2E测试套件**。没有把其他聊天的历史结果当成本轮结果。

当前是单进程内存存档，后端重启仍需重开会话；未接SQLite。尚未建立完整多主体知识图谱、长期偏好画像或通用故事编辑器。正式原创角色、真人听感、移动真机和生产网络不在本轮验证范围。自由语言的语义/事实一致性不是schema能百分百证明的，当前采用最小知情上下文、合法动作约束和推荐过滤。

补充实际路线：新会话在未打开信件的情况下，通过进店与陪伴路线，也能解锁决定并完成《再坐一杯》，最终停留窗边、保留一盏灯。对应本地截图 `06-companionship-ending.png`。

额外资源边界：已提交或最终冻结后不再需要的候选存档会释放；候选操作最多十beat、四个语音片段；取消时回退未确认旁白，保留已确认前缀。生成bytecode由构建准备生成并被Git忽略，同样内容的重复编译不重写artifact。
