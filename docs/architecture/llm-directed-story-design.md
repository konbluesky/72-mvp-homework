# 剧情导演与 LLM 会话分离

2026-11-02，运行包 `last-lamp@4.0.1`。本页描述当前代码；模型自然度、真实语音和完整路线时长仍待手测。原 3.x 的逐句推进、固定玩家例句和快捷跳段混合机制已从当前剧情包移除。

## 当前职责

| 模块                               | 负责的内容                                                                         |
| ---------------------------------- | ---------------------------------------------------------------------------------- |
| `cafe/character.json`、`lore.json` | 成年空乘米拉的人物设定、事实与公开条件；初识有保留，交流有依据后再熟悉             |
| `cafe/chapters.json`               | 两次见面共 16 个交流段落的目的、话题、机会、分寸和节奏；不指定玩家下一句           |
| `cafe/main.ink`、分场 Ink          | 共桌、移动、展示物件、可选游戏、短暂离席、返回、另约、接触与结局                   |
| `manifest.json`                    | 资源、投影、下一步事件映射、必要短台词及独立角色意愿复核条件；没有 `playerReplies` |
| LangGraph                          | 普通回复与推荐生成、意图复核、事件后的接话、结构校验与取消隔离                     |
| SessionManager / PlaybackScheduler | 仅回执确认后提交 checkpoint；声音、字幕、旁白、动作和呈现回执仍由原调度器控制      |

`met` 只表示见过面，`companionship` 只表示眼前共桌或同行。没有按轮次增加的好感分，也没有走完某个章节就设置的 `trust`。`chemistry` 记录双方愿意进一步了解，须先经过独立角色意愿复核，再由该事件的呈现回执提交；不表示恋爱、排他关系或身体接触许可。

## 每轮交流

普通文字和语音输入沿用同一 Graph：以已确认场景、当前章、人物背景、真实已呈现历史和当前原话，生成短回复与推荐。普通回答、反问、分享和玩笑不再选择一个逐句 talk 动作来换取下一句。通常一至两句，话题简单时可以只答一句。

回复不能预设玩家停顿、吃醋、心事或感受；“我同意”“你看出来了”等承接语需要实际前文。咖啡、风景画、菜单是可选话题，不承担必须完成的线索任务。冲突只承接实际发生的不舒服，不再固定安排职业盘问、冒犯、道歉和修复。

两页的推荐仍只发送自然发言，经过当前输入语义解释后才可能形成行动请求；不绑定执行。每次推荐依据刚生成的回复和当前合法事件，可少给或不给，不重复已完成的邀请和介绍。

## 事件与后续回复

1. 从当前合法事件解释请求，保留完整输入证据；关键明确意图继续独立复核。
2. Ink 只提议事件和对应 checkpoint，不预写普通聊天答复。
3. 播放器按依赖呈现。Graph 等待成功回执；SessionManager 提交后，才能把事件作为事实交给模型。
4. 使用确认后的场景、真实历史和本次输入，生成自然承接与同一次回复的推荐。按钮动作以 `completedInteraction` 表示，不冒充玩家说过的台词。
5. 上游失败或输出无效时保留已经确认的位置，报告回应失败；不回退到脱离上下文的固定长句。

保留的固定短台词仅包括必要的初见招呼、离席说明、小游戏题目/答案，以及确实已经独立复核过的简短接触意愿。这些台词播完后只生成推荐，避免再次打招呼或重复表达；没有固定台词的事件才生成后续对白。

普通交流通常一次 planner 调用。自然语言关键动作沿用额外意图复核；场景事件完成后会再调用 planner 生成接话。角色意愿复核会使涉及双方的按钮请求也产生一次 planner 调用。外部等待不计为有效剧情时长。

## 她可以保留或拒绝

`manifest.actionReview` 定义涉及双方的选择：表达双向兴趣、恢复约会方向、再次邀约、共度一夜、各项身体接触和需要双方同意的关系形式。

文字、语音和直接点击统一在 Graph 内独立判断：当前玩家是否明确请求，结合实际相处，她是否也愿意。按钮只证明玩家提出请求。没有足够双向交流、她想保持距离或双方期待不一致时，返回她自己的简短回应，按普通对话播放，不执行事件，也不写关系标记。

停止、放慢、朋友和离开保留可执行的出口，不需要玩家说出标准答案。复核后若轮次或 revision 已变，旧结果不得继续执行。

这是依赖实际上下文的模型语义判断，不是结构校验能够保证的人物自然度；需通过不同措辞、拒绝、转话题和长聊的手测评估。

## 两种推进方式

保留自由聊天和常驻手动推进。当前章可以聊多轮，不随普通回答自动换段。手动推进的目标名称来自服务端许可的下一项事件/话题，与自然语言请求共用 checkpoint。

转移只改变实际位置、话题焦点或已经完成的事件。不会把未聊过的内容补成记忆，不授予心动或亲密，也不会跳过共度一夜的再次明确选择。角色独处时只保留等候、继续与结束，玩家仍在原处。

## 前端、版本与验证

现有八张场景、风景画/饮品单/咖啡等当前物件、Live2D、真实语音播放与回执继续使用。章节和角色意愿条件不进入公开 manifest，前端只展示服务端当前动作；本轮没有新增 Mock 语音或文字替代协议。

编译同时校验私有章节与动作引用，章节文件也参与 artifact hash。4.0.0 不兼容旧逐句存档，需刷新并明确开始新会话；不静默清理草稿和回看。

已维护场景、事件后生成、按钮保留/拒绝、回执前后、迟到结果与边界相关回归源码。遵守用户要求，本轮不执行功能、运行时或 E2E 测试，不启停服务、不调用外部模型或语音。静态检查结果见本轮交付记录。
