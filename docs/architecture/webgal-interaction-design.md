# WebGAL 持续会话

2026-11-01。本文替换此前已否定的“导航、观察、剧情选择、自由聊天”多入口方案。范围为 `/webgal.html` 的第 1–3 点：持续可见的会话、直接发送的自然回复建议、角色引导的初次相遇。第 4 点“是否及如何直接点场景物件”仍待用户决定。本轮保留已有观察、物件动作和回执能力，不重定义点物件的含义。

## 用户体验

舞台和 Live2D 角色是视觉主体。角色名字与身份在舞台中靠近角色显示；下方是一处始终存在的近期对话、下一句话和输入区。玩家发言采用右侧、稳定宽度的高对比文字气泡。旁白与内心独白显示在舞台叙事层，不再进入近期聊天列表。桌面根据角色位置选择留白侧，心声靠上、旁白靠近舞台下沿；手机在舞台下沿以“旁白／心声”切换显示，完整文字可在面板内滚动。近期区保留六组内容，历史从三点菜单中的“对话回看”访问；回看在当前浏览器保留最近 60 条已显示内容，半句被打断的台词也可能留在历史中，不是“已听完”的证明。草稿、输入偏好和角色外观也在浏览器保存；会话有效期内可先补交真实回执再恢复服务端快照，失效后保留回看与草稿并要求明确重新开始，见 [ADR 013](decisions.md#adr-013--浏览器侧保存与短期会话恢复)。

没有“自由对话”“回到剧情”“接话灵感”或独立剧情回应面板。角色说话、转场或展示资料时，会话与输入继续留在原位。正常界面只显示位置、已有观察入口、故事菜单和必要的资料/失败反馈。地点快捷入口收进故事菜单，八个地点仍是可访问的内容资源，用户不需要按地图路线完成导航任务。

会话从已布置好的大堂与角色的一句邀约开始。开场文字和候选由后端故事包给出，文字开场不伪造语音播放或呈现回执。建议通常为 2–3 条玩家自然会说的话；其中可以有接受邀请、陪伴或转话题的表达。角色可邀请看照片、读信、换位置，也允许拒绝和继续闲聊。内容参考在 Ink/validated JSON 中，前端不复制剧情状态、道具正文或关键词路由。

## 发言与确认

推荐直接显示在同一会话区，文字/语音输入切换不隐藏候选；录音、识别、待确认语音稿、演出进行中、失败或已有手写稿时暂停展示。点击闲聊候选把 `draft` 作为玩家文字发言发送；故事包明确编写的动作候选可携带 `interaction`，点击后通过已有 Graph interaction 分支校验当前动作与 revision。录音松开后仍先识别为可编辑草稿，确认后才发送，不再常驻重复的录音操作注释。

`ReplySuggestionSchema` 为 `{label,draft,interaction?}`。interaction 仅由服务端故事包绑定，模型 schema 不允许输出该字段；模型提议关联动作时，只有能匹配故事包当前候选的项才替换成故事包编写的发言与动作。候选生成不授权执行，点击后仍校验当前动作、revision 和轮次，实际呈现成功后才提交 checkpoint。严格旧客户端需要与后端一起更新并刷新。

`explicit` 表示动作需要明确的用户意图或确认，文字、语音与推荐都可以表达；它不表示只能点专用按钮。Graph 校验当前允许动作、完整用户发言证据、confirmed、revision 与有效轮次，再交给 Ink 提议。自然语言输入中的关键选择与读信额外在 Graph 内进行独立确认复核，只允许复核同一动作；否定、假设、询问后果、引用他人、含糊附和不能被当作授权。未通过确认时转换为角色追问或普通交流，不执行另一个选择。Live 语义识别仍依赖模型判断，关键动作的复核会多一次 planner 调用；不能把静态检查当成所有自然语言表达都已经验收。Mock 的关键选择只接受故事包已编写的明确发言，离线匹配不承诺覆盖所有同义表达。

动作执行仍由服务端白名单、Ink 当前状态和 revision 约束。客户端不信任模型生成的标识或资源地址。物件快捷操作保留现有 `actionId/revision` 路径，未将“点击信封即询问信是什么”等待定方案当成已批准行为。

## 演出与并发

- 用户消息绑定稳定的 messageId；两个入口共用 TurnController 的发送、等待、回应、完成、失败与打断状态。完全未回应的失败消息在原气泡旁显示红色重试按钮，点击保留气泡并创建新执行，不追加重复发言。仅最新、可重试且尚无实际呈现的消息允许原位重试；已被新消息或录音意图替代的旧消息保留失败/打断状态。语音草稿确认后重试的是最终文字。
- 重试先核对会话快照与冻结回执，网络恢复不自动提交输入。部分呈现、主动停止与浏览器音频播放失败独立处理；原有重试声音/阅读文字仍由 Scheduler 负责。阅读记录保存 messageId，消息状态与会话一起恢复；会话失效后保留阅读状态但禁止直接重试旧会话。

- `reply.done` 只表示生成完成。PlaybackScheduler 等队列、声音和呈现结束后才发布候选；呈现失败不显示候选。
- 候选点击再次检查当前候选数组身份、当前状态和开场 revision。首个发送同步开始新轮并清空建议，因此旧按钮与重复点击不能提交第二次旧候选。
- 玩家自己输入或开始录音可以打断当前回应。旧网络结果、确认复核和 finally 均需检查轮次身份；旧轮不能影响新轮。
- 照片、环境、正文、移动和结局继续由实际呈现回执确认；SessionManager 独自提交 checkpoint。取消冻结回执，开场、历史和候选不产生事实。

## 顶栏与推荐推进修复（2026-11-01）

原版 Vue `/legacy.html` 与默认 React/WebGAL `/`（兼容入口 `/webgal.html`）是独立技术入口，各自创建会话。两边顶部均提供同标签页的版本切换，替代 Live 标签；回看与重新开始统一放进菜单，开发演出预览移出故事菜单。原版仍是固定座位对话，移动、读信与结局由 WebGAL 承担，不把不能呈现的动作开放给原版。

回看弹窗固定不透明标题，仅正文滚动，避免历史文字穿过标题。推荐默认提供明确行动与陪伴/陈述的不同方向；未知的旅行和展览细节不继续循环追问。动作完成后的推荐从目标 Ink checkpoint 生成，不采用执行前模型给出的旧推荐。

地点“巷口咖啡馆”和天气“深夜 · 有雨”维护于 `apps/web/src/webgal/scenes/cafe/legacy.ts`；WebGAL 地点名、开场和编写的推荐位于 `apps/server/src/scenario/cafe/manifest.json`，剧情与道具分别位于同目录 `.ink` 和 `lore.json`。

浏览器排查还发现：吧台/窗边/洗手区前景从 Pixi 全局 TextureCache 读取背景，但纹理由舞台 AssetManager 管理，转场会报 `CAFE_FOREGROUND_TEXTURE_NOT_READY`。现将已经就绪的舞台背景纹理直接传入前景绘制，仍由调度器确认呈现。

本次实际通过 typecheck、修改源码 ESLint、modules:check、assets:check、scenarios:check、contracts:generate/check 与 diff 空白检查；未执行自动化功能、运行时或 E2E 测试。按用户授权使用 agent-browser-cli 复用现有 dev 服务，顺着推荐实际完成等候→照片→陪伴→吧台→读信→离店，在店外街道到达《下一站，由我决定》。未手工启动、停止或重启 dev 服务；开发监听器会在源码和构建产物更新时自行重载。

## 2026-11-01 推荐与剧情推进热修

固定推荐不再覆盖LLM生成内容，正常对话推荐只保留模型本轮的label/draft，点击后作为普通发言提交并重新解释意图。开场和剧情运行时不再将playerReplies/chatReplies直接发布为推荐。剧情动作确实呈现后，在LangGraph内用最新确认状态与已听对白生成推荐；该生成失败时可留空，不回退到旧固定句。

非explicit的交流进度允许LLM从实际回应判断完成，不要求复述剧本句子；符合条件的普通交流节点使用模型生成的自然回应。涉及地点、物件、事实里程碑或亲密意愿的演出仍保留明确请求和确定性锚点，回执提交与取消冻结不变。不按轮数推进，也不因模型输出就宣告已呈现。

右上角改为“下一步”，优先显示当前合法剧情环节和选择；可选场景物件放在次要区域。动作标签描述剧情机会，回复推荐仍是用户发言，两者不混用。独处时保留显式等候和结束操作。剧情包升级为3.0.1，需要刷新后明确开始新会话；不会自动删除浏览器里的历史和草稿。

按用户要求未运行测试、浏览器对话或付费Provider；只执行编译和静态核对。整仓类型结果若受其他同时修改的代码影响，会在交付中说明。

2026-11-02 收尾：普通交流步骤在同次LLM规划中保留自然回应和推荐，满足当前要点时推进；固定事实/演出节点实际呈现后再基于新状态生成推荐，不回填旧固定句。新增对用户已说过原句的过滤。右上角“下一步”显示服务端当前合法进度，可选物件单独标注。最终通过typecheck、修改生产源码的定向ESLint、scenarios:build/check、格式与Git空白核对；未运行测试、浏览器交互或付费调用。

## 舞台叙事与手机布局

WebGAL近期聊天过滤narration记录，保留双方对白、开场和既有交流内容；旁白与心声继续原样保存在对话回看，不删除阅读历史。舞台直接读取PlaybackScheduler投影的narration，按既有“旁白｜…心声｜…”格式分开呈现，不新增网络字段、计时器、回执或剧情状态。

桌面把两种文字放在角色留白侧，随当前镜头中的角色位置左右切换；展示资料、展开场景操作或舞台未就绪时收起叙事层。独处状态与镜头地点也显示在舞台，玩家位置不因此改变。短高度横屏使用左舞台、右对话布局，避免把舞台挤成窄条。

手机叙事栏位于舞台内下沿，旁白与心声一次显示一种，通过44px触控按钮切换。长文可滚动，不省略正文；小屏减少聊天区高度，极短窗口允许页面滚动，保持输入可到达。已通过无API调用的静态组件布局预览查看1440×900、390×844、320×568及844×390；预览使用现有背景与Haru静态素材，不是业务对话或真实Live调用验收。未启动或重启服务，未提交角色对话，未采集麦克风，未执行功能、运行时或E2E测试套件。
