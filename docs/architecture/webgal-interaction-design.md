# WebGAL 持续会话

2026-11-01。本文替换此前已否定的“导航、观察、剧情选择、自由聊天”多入口方案。范围为 `/webgal.html` 的第 1–3 点：持续可见的会话、直接发送的自然回复建议、角色引导的初次相遇。第 4 点“是否及如何直接点场景物件”仍待用户决定。本轮保留已有观察、物件动作和回执能力，不重定义点物件的含义。

## 用户体验

舞台和 Live2D 角色是视觉主体。角色名字与身份在舞台中靠近角色显示；下方是一处始终存在的近期对话、下一句话和输入区。玩家发言采用右侧、稳定宽度的高对比文字气泡。场景旁白采用较弱文字层级。近期区保留六组内容，历史可直接“回看”或从菜单访问；回看只保留本页最近 60 条已显示内容，半句被打断的台词也可能留在历史中，不是“已听完”的证明。

没有“自由对话”“回到剧情”“接话灵感”或独立剧情回应面板。角色说话、转场或展示资料时，会话与输入继续留在原位。正常界面只显示位置、已有观察入口、故事菜单和必要的资料/失败反馈。地点快捷入口收进故事菜单，八个地点仍是可访问的内容资源，用户不需要按地图路线完成导航任务。

会话从已布置好的大堂与角色的一句邀约开始。开场文字和候选由后端故事包给出，文字开场不伪造语音播放或呈现回执。建议通常为 2–3 条玩家自然会说的话；其中可以有接受邀请、陪伴或转话题的表达。角色可邀请看照片、读信、换位置，也允许拒绝和继续闲聊。内容参考在 Ink/validated JSON 中，前端不复制剧情状态、道具正文或关键词路由。

## 发言与确认

推荐直接显示在同一会话区，文字/语音输入切换不隐藏候选；录音、识别、待确认语音稿、演出进行中、失败或已有手写稿时暂停展示。点击候选即把 `draft` 作为玩家文字发言发送，与输入或说出同一句话使用同一 Graph 和服务端校验。录音松开后仍先识别为可编辑草稿，确认后才发送，不再常驻重复的录音操作注释。

`ReplySuggestionSchema` 保持 `{label,draft}` 的形状，无动作 ID 或 URL。它的注释和调用语义已同步为直接发送，候选本身不授权执行。此次交互语义调整不再额外提升事件版本；场景模块化带来的版本变化由对应工程记录说明。

`explicit` 表示动作需要明确的用户意图或确认，文字、语音与推荐都可以表达；它不表示只能点专用按钮。Graph 校验当前允许动作、完整用户发言证据、confirmed、revision 与有效轮次，再交给 Ink 提议。关键选择与读信额外在 Graph 内进行独立确认复核，只允许复核同一动作；否定、假设、询问后果、引用他人、含糊附和不能被当作授权。未通过确认时转换为角色追问或普通交流，不执行另一个选择。Live 语义识别仍依赖模型判断，关键动作的复核会多一次 planner 调用；不能把静态检查当成所有自然语言表达都已经验收。Mock 的关键选择只接受故事包已编写的明确发言，离线匹配不承诺覆盖所有同义表达。

动作执行仍由服务端白名单、Ink 当前状态和 revision 约束。客户端不信任模型生成的标识或资源地址。物件快捷操作保留现有 `actionId/revision` 路径，未将“点击信封即询问信是什么”等待定方案当成已批准行为。

## 演出与并发

- `reply.done` 只表示生成完成。PlaybackScheduler 等队列、声音和呈现结束后才发布候选；呈现失败不显示候选。
- 候选点击再次检查当前候选数组身份、当前状态和开场 revision。首个发送同步开始新轮并清空建议，因此旧按钮与重复点击不能提交第二次旧候选。
- 玩家自己输入或开始录音可以打断当前回应。旧网络结果、确认复核和 finally 均需检查轮次身份；旧轮不能影响新轮。
- 照片、环境、正文、移动和结局继续由实际呈现回执确认；SessionManager 独自提交 checkpoint。取消冻结回执，开场、历史和候选不产生事实。

## 验证边界

新增候选过期/重复点击、语音稿门禁、完整输入证据、Graph 确认拒绝/取消/revision 变化等回归测试源码。遵守仓库限制，本轮不执行功能、运行时、E2E 或 `npm run check`。类型、lint、构建、场景和契约静态检查的实际结果见交付记录。未采集麦克风、未调用付费探针、未启动或重启服务。真实语音听感与连续 3–5 分钟交互仍需用户授权后验收。
