# HTTP / SSE 连接监测与自动恢复

当前产品沿用 HTTP + SSE，没有新增 WebSocket 业务链路。下行回复、字幕/动作/照片意图、推荐项是结构化事件；文字、录音上传、取消与回执走 HTTP POST，私有音频走 HTTP GET。当前按住录音模式不需要全双工音频长连接；未来自然双工/WebRTC需求另行评估。引擎自带的编辑器同步通道不参与此机制。

## 页面与链路

顶部状态入口展示连接状态和最近 HTTP 往返毫秒数，点击可查看 SSE 通道、会话状态、最近探测成功时间与监测错误，并主动重连。会话过期时提供明确的重新开始入口。

服务、会话和单次请求分别判断，会话栏反映最近一次会话请求的确认结果，心跳不充当会话鉴权：服务可达不等于会话仍有效，也不证明 GPT/Deepgram 的权限、额度或远端可用性；一次业务失败不直接变成整个服务离线。

| 接口                         | 用途                                                            | 预算/成本                                                       |
| ---------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------- |
| `GET /api/connection/events` | 常驻 SSE；首帧 connection.ready，随后每5秒 connection.heartbeat | 不创建会话、不调用模型；单进程最多200条；慢消费者不无限排队     |
| `GET /api/connection/ping`   | 无敏感 JSON，采样完整 HTTP 往返耗时                             | 每次完成后5秒再探测，单次3秒预算；不携带会话令牌或cookie        |
| 原 `/healthz` / `/readyz`    | 存活/加载模式检查                                               | 保留既有运维语义；Compose nginx也明确转发，避免SPA页面的200误判 |

RTT用浏览器同一performance.now时钟测量，从发出到收到并验证JSON完成，包含代理、服务端处理和浏览器调度；不是单向网络时延、SSE事件的跨机器时钟差或模型首音时延。未取得有效样本或探测失败时显示 `--`，不沿用旧值冒充实时值。

帧协议由 `packages/protocol/src/index.ts` 的 strict ConnectionEventSchema/ConnectionProbeSchema 定义，生成到OpenAPI。健康SSE有独立connectionId和从1开始的连续seq，没有聊天身份、私有媒体或凭证。它是无状态快照，重连不需要回放旧健康事件。

## 重连与所有权

- 5秒内须收到首个有效ready帧；15秒内须持续收到有效类型的心跳。仅收到注释/任意字节不能无限维持应用层健康。
- SSE结束、格式/序号异常、心跳超时后按1、2、4、8、16、最多30秒退避重连，带少量随机抖动；一个页面只有一个当前连接和一套计时任务。
- HTTP连续两次失败且SSE也不可用时，才将服务标为不可达并通过现有控制器停止当前工作。SSE重连但HTTP正常时仅降级监测，不取消有效播放。
- 监测端点返回404、鉴权拒绝或200但schema不符等可达响应时显示监测异常，不把它们直接当整台API离线。具体HTTP错误显示状态码，网络错误/超时/协议异常分别处理。
- 所有连接/探测使用独立epoch与AbortSignal；晚到响应、旧finally、旧重试不能改新状态。挂起/卸载清理重试、deadline、socket/reader与监听；服务端preClose主动关闭常驻流。
- 后台关闭监测并取消正在恢复的HTTP请求，返回前台重新探测与确认会话。浏览器offline会立即停止工作；online只触发恢复，不直接假设连接已成功。

会话等控制JSON请求有10秒总预算（覆盖响应体解析），不会永久卡在“连接中”。转录预览包含上传、解码与STT，采用独立的120秒客户端上限并继续服从服务端预算及用户取消，不套用10秒控制请求预算；长SSE与音频播放也保持自身预算。健康探测另有3秒预算。

## 会话恢复与业务SSE的边界

自动恢复只处理未连接且没有有效活动轮次的会话，不在每个心跳调用会打断当前轮次的connect。已有会话先补交未确认呈现回执，再读取快照，保持generation单调与已呈现事实。恢复过程同样检查自己的epoch；后台或新会话已替代旧恢复时，迟到响应无权写状态。

服务重启/会话过期/认证失效时停止自动创建新会话，明确让用户选择重新开始。不会悄悄重置剧情。尚未发送的输入框文字保留。

会话初始化返回不可重试错误时，停止自动重试（包括监测恢复、online和前台恢复触发），保留错误供用户查看；修复后可手动重试。未知内部异常返回 `INTERNAL_ERROR` / 500 / 不可自动重试，不冒充供应商故障。429 采用至少 60 秒的会话连接冷却，主动重连和强制恢复也不绕过；同一控制器的并发初始连接合并为一次请求。开发/演示默认关闭创建和输入的本地频率限流，详见[开发配置](../development/README.md#演示限流)。

**对话POST SSE异常中断后，不自动重发原输入，也不重播旧事件。** 现有服务端会取消该stream对应任务，而且协议没有承诺事件日志重放；盲目重试POST会重复生成/计费。页面恢复连接和会话后可由用户重新发送，正常SSE EOF仍让已有效排队的播放完成。

如未来要求接续一条未完成回复，应单独设计持久/有界事件日志、Last-Event-ID/游标、呈现进度和单次生成语义；这不属于本次重连实现，也不能靠浏览器自动重试POST替代。

## 部署与验证范围

所有新接口位于 `/api/`，复用既有Vite/Compose/生产nginx的HTTP代理及CORS。SSE继续关闭buffering/cache，响应提供X-Accel-Buffering:no；不需要Upgrade配置或WS依赖。跨域Pages使用同一个VITE_API_BASE_URL，健康通道也只请求该API origin。

先部署带新接口的后端，再部署前端。前端遇到旧后端不支持监测时显示异常而不是伪造绿色状态，既有业务传输保留。新增来源只允许配置过的Origin，不由模型控制URL。节点仍遵守当前单进程/单实例会话约束。

已补充以下测试源码：流容量/关闭/背压、首帧关闭竞态、迟到探测、心跳缺失、SSE重连、HTTP可达而监测不可用、挂起/清理、请求deadline、会话恢复无输入重放、会话过期不重建、旧快照迟到、健康帧拒绝额外凭证。

按当前AGENTS约束，本次不执行功能、E2E或运行时测试，不调用真实Provider；编译、lint、构建与契约生成/校验是本次验证范围。实际断网、代理中断、后台恢复及浏览器端RTT需在用户明确要求后运行验证，不以编译通过冒充验收。

语音NO_SPEECH单独作为输入问题返回422，不能触发离线/重建会话。正常监测ping/events路由使用warn日志级别，避免每5秒的成功请求info刷屏；监测逻辑与采样频率没有因此改变。
