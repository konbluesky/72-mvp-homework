## 场景方案与补充要求

先读 [Miara + WebGAL 八场景叙事方案](../miara-webgal-scenario-design.md) v0.2。该文档是实施前设计，不是已交付记录；本版替换此前“三个机位视图”的范围，以下产品目标与原有 A–E 要求一并落实。

- 首版采用《雨停之前：最后一盏灯》：旧咖啡馆最后营业夜，Miara 等待旧友，玩家经探索发现署名给她的留言，并选择主动出发、留下回信或继续陪伴。固定真相、三幕、三结局以方案第 4 节为准，不让模型临时改写真相或替玩家选择。
- 设计并交付八个独立背景：街角咖啡馆远景、门头近景、入口大堂、窗边座位、照片墙走廊、卫生间公共洗手区、吧台结账台、店外街道。至少五个真实背景是硬门槛，目标为全部八个；同图缩放、照片/信件特写、换雨势/亮度不计作新背景。
- 满足三情绪、两种非说话行为和三种新编人物动作；人物动作单独验收，不替代地点与环境变化。完成进店、读信、留信、翻牌、熄灯、离店雨景等有剧情因果的演出，正常故事约 10–15 分钟，另提供经过至少五背景的 3–5 分钟精简路线。
- 补齐拒绝照片、暂不读信、先后不同的探索、回访与三种结局。新版天气规则改为：角色已同意离店，门头/街道实际呈现后可雨势缓和，与照片是否展示分别判断。同步替换 scenario 规则、Graph 照片等待/环境筛选、SessionManager 依赖、Scheduler 阻塞、Mock 与 fixtures，不只改 prompt。
- 场景上下文包括当前地点、在场人物、固定真相、已公开线索、选择和资源语义。当前海岸照片没有人物，联展署名来自新海报，朋友的留言来自新信件；未呈现正文不能提前泄露，信封不等于读信成功。
- Miara 的原始 motion 三段均为循环配置，并混有人物、精灵、水面和全局曲线。核实实际部件索引与依赖，处理不适用的样例背景/水面/反光；保留原始文件，不自动循环全通道动作，不将精灵运动当作人物行为。
- 同舞台融合需处理现有背景里已经画入的桌面/杯子/纸张、窗外雨遮罩、统一多层镜头及响应式热区；不能直接覆盖重复道具，或只缩放背景而宣称完整镜头演出。
- 点击、导航与选择通过受校验的 interaction 意图进入既有 input/Graph/调度链；location、prop、ambience 分别建模与回执，照片继续使用 photo 许可。纯导航可走 Graph 内确定性分支，并新增受控 presentation.ready 下发/队列，不伪造 audio.ready 或每走一步调用 LLM/TTS。具体增量见方案第 8 节，同步版本、路由、客户端、Mock 与 OpenAPI。
- 补足动作进入/保持/退出/取消句柄，短前奏与镜头时机由 Scheduler 的本地 cue 编排管理；音频结束不等于所有视觉动作结束。开发预览与业务演出互斥，不写事实、不另起播放器。
- Mock 新分支必须有匹配的离线音频或复用语义一致的已有素材；当前 MockTts 按完整台词读取固定 WAV，不能只新增文本造成声音失败。新增音效也需本地资源、归属和统一取消治理。
- 业务角色 Mira 与默认渲染模型 Haru 分开。调整不匹配画面的外形提示词，保留原创成年剧情身份及两种样例归属；正式原创视觉资产仍是原始需求的交付缺口，不能以更换官方样例打勾。

工程顺序应同时收口 B1 状态/输入、B2 Bridge/呈现事务与 B3 角色/场景；只有同页对话与演出链完成后才能接管默认产品入口。本节及方案不新增功能、运行时或 E2E 测试执行授权。

## 需要交付的体验

### A. Haru 默认展示，Miara 显式可选

- 在 WebGAL 页面中默认渲染 Haru，保留 Miara 的显式切换；人物、背景、道具与特效纳入现有舞台/适配端口；提供容易发现的产品入口和角色切换入口。
- 用角色注册表描述模型、本地资源、参数映射与能力；拆开 Haru 加载器对单一文件名/参数的硬编码，分别保留 Miara 和 Haru 适配配置。
- 现有 Vue 页面与 WebGAL 为两个独立入口，均须保留并提供可见切换；完成新页迁移不意味着可以删除原版或改变用户已调好的交互。
- Miara / Haru 加载、取消、切换、销毁各有明确归属；切换中失效旧异步结果，旧实例不得销毁新实例资源。切换需进入安全轮次边界或显式执行现有打断流程。
- 保留 Haru 全部现有模型文件、归属、poster 与实现。Miara 失败时显示错误和重试，并让用户显式切换 Haru；不能拿 Haru 的 poster 冒充 Miara。
- WebGAL 宿主复用锁定的依赖与既有 Cubism 入口，避免从旧 Vue vendor 脚本再加载一套 Pixi/Live2D，避免两个 canvas、ticker 或音频播放器竞争。

### B. 聊天、语音和四态

- 打通文字输入、回复字幕、真实音频播放、打断及下一轮恢复。录音入口跟随 `session.capabilities.voiceInput`，不根据 Mock/Live 名称猜测能力。
- 默认 Mock + Local 无密钥可用。Live 继续 Deepgram STT + GPT/LangGraph 规划 + Deepgram TTS，缺失配置明确报告，不静默降级到 Mock，不调用付费 Provider 做探测。
- 待机、倾听、思考、说话要能从角色姿态直接辨认，不能只换状态标签。倾听可前倾、聚焦玩家；思考可偏头、移开视线并调整眉眼；说话保持交流视线，口型由当前实际播放音频驱动。
- Miara 清单中的口型/眨眼 `Ids` 与 `HitAreas` 为空。核实 `.moc3` 中实际嘴部/眼部参数后接入，不依赖空配置的自动能力；必要命中区域由本地交互层实现。
- 文字降级、等待权限、等待生成与真正 speaking 分开表达。`reply.done` 只表示生成完成，不代表已播放或已呈现。

### C. 自定义动作，不能只有 Scene1–3

- 保留原始 `Idle/Scene1`、`Tap/Scene2`、`Flic/Scene3` 作为可选展示；注意组名是 **Flic**。
- 基于真实参数范围，新编至少三种可辨认人物行为：**抬手示意、偏头沉思、看向窗外再看回玩家**。它们应是新参数曲线或新动作文件，不能只是将 Scene1–3 改名；它们属于人物表演，不计为本版要求的背景场景变化。
- 可检查 `ParamArmL1/L2/L3`、`ParamArmR1/R2/R3`、头部/眼球、身体和 `ParamLegL*` / `ParamLegR*`。CDI 名称只是线索，必须验证真实索引、最小/最大/默认值；未知参数不得依赖 wrapper 自动虚构的索引。
- 区分人物、精灵和舞台通道；部分带 `F` 的参数属于精灵。为自定义动作设置进入、保持、退出、取消与回到当前基础状态的行为。
- 制定清晰的参数混合与优先级：原始 motion、自定义行为、表情、视线、物理、眨眼及口型不能互相覆盖。别每帧把所有参数写死；原始动作携带的嘴部曲线不能抢走实际音频口型控制权。
- 坐下、起立、托腮、端咖啡先做已有绑定的能力评估。能用现有参数自然完成就编排；需要补图或编辑工程时记录缺口。不能用整张立绘位移冒充完整坐站动作，也不能在没有手型配合时声称真实握杯。

### D. 场景切换和 WebGAL 动效

- 按方案制作全部八个独立背景并打通地图，至少五个真实背景为交付硬门槛。每个地点要有独立构图、本地资源、人物锚点、可达出口、互动/剧情作用和状态变体；不能只用同一背景裁切或改雨势凑数。新增图与来源清单必须真实落盘，当前旧 SVG 只可复用于对应地点。
- 使用 WebGAL 原生背景状态、变换、动画和 Pixi 特效能力，经受控适配器执行；不能只在 WebGAL canvas 上覆盖一套完全独立的页面动画就声称完成集成。
- 室内雨位于窗外，室外雨有合理深度与雨棚遮挡；门、营业牌、灯光、信纸、回信通过 WebGAL 同舞台执行。八个地点的人物站位、热区、声场与镜头一致，转场不能只换图而留下旧出口。预览控件放开发面板，产品地图按真实可达关系导航。
- 场景切换有资源就绪、过渡、取消、失败与重试处理；快速连续切换时只保留最后有效请求，旧 finally 不得还原新场景。
- 区分手动视觉预览与会话内剧情变化。预览切换不伪造业务事实；若某个变化要影响下一轮聊天，则扩展受校验的语义事件与独立呈现回执，再在服务端提交事实。

### E. 点选、物件和聊天联动

- 至少实现窗户和照片两个可发现、可键盘操作的交互目标。点击窗户：Miara 看向窗外，镜头转向窗边，可围绕天气继续聊；点击照片：她低头关注照片，照片进入近景，并支持围绕照片继续聊。
- 交互层提交语义意图，统一进入既有轮次/调度流程；录音和新输入仍可打断。能改变剧情的交互不能绕过当前轮次所有权。
- 对话可触发白名单行为，例如“看窗外”“给我看看照片”“换到窗边”。资源 URL、模型名、目标对象 ID 和脚本都由本地注册表/服务端生成，不能由模型任意指定。
- 补齐停业告示、联展海报、署名信封/信件正文、回信与营业牌互动；每个物件与所属地点及已确认剧情绑定。“去吧台”“回座位”“出去走走”等自然语言进入相同语义路径。拒绝照片不阻断主线，结局不能靠点遍所有道具解锁。
- 照片成功呈现与环境成功变化分别提交回执。取消时冻结已呈现事实，下一轮不能确认失败或尚未展示的内容。

## 架构与交付约束

- PlaybackScheduler 继续是声音、字幕、动作启动和呈现回执的唯一调度者。WebGAL 负责执行；不得开启第二条自动剧情推进、原生配音或随机点击语音管线。
- 保持 interactive 模式与原生 story 推进的隔离。不要让 LLM 生成任意 WebGAL 脚本后直接交给 parser/runScript。
- `apps/web`、`apps/server`、`packages/protocol` 保持现有依赖方向。新增网络字段要在 `packages/protocol/src/index.ts` 中使用严格 schema 校验，并重新生成 OpenAPI；纯本地预览参数无需扩展网络协议。
- 每个异步副作用检查完整 turn identity；同时检查场景 revision、stage lease/epoch、角色实例归属。取消、重建、重连和销毁不能重播旧内容或污染新轮次。
- 复用当前连接健康与会话恢复设计。记录音频、密钥和私有媒体不得进入资源目录、日志或报告。
- 更新实际迁移记录、资产哈希和来源文档。注明哪些能力已实现、哪些仅有静态证据、哪些经人工视觉调试确认、哪些仍缺少资产；保持两种角色归属说明。

## 实施顺序与验证

先核对基线，再按“故事/八背景美术基准 → 角色适配与参数动作 → 同页聊天播放闭环 → 大堂/座位/吧台切片 → 全八背景与三结局 → 生命周期与交付收口”推进。三地点切片是开发阶段，不满足最终至少五背景门槛。分阶段交付可以运行的结果，不以构建通过代替体验完成。

遵守 `AGENTS.md` 的测试限制：本 prompt **不新增功能测试、运行时测试或 E2E 的执行授权**，不要运行含这些测试的 `npm run check`。修改生命周期/协议时补有意义的测试源码，但将执行留待用户明确要求。可在既有约束允许范围内做手动浏览器视觉调试，明确区别于测试套件，不把视觉调试当作完整业务回归。

使用固定 Node 26.13.0 / npm 11.20.0；需要安装依赖时使用 `npm ci`。静态检查按改动范围执行：类型、lint、格式、构建、`npm run assets:check`、`npm run webgal:check`；协议变化时执行 OpenAPI 生成与 `npm run contracts:check`。使用项目 runtime launcher 解决系统 Node 版本差异。

最终给出可访问入口和简短操作步骤，至少覆盖：

1. Miara 与 Haru 显式切换，Haru 资源完整保留。
2. 真实聊天与可辨认四态，口型跟随实际音频。
3. 至少三种新编动作，并说明与原始 Scene1–3 的区别。
4. 八个独立背景与地图、三幕三结局、留信/翻牌/熄灯/街道雨景，说明背景文件与人物动作分别如何验收；精简演示至少经过五个真实背景。
5. 打断、快速场景切换、加载失败和角色切换的处理证据及未验证边界。

没有编辑工程或专用握杯/坐站绑定时，如实列出缺口；继续完成不依赖这些资产的部分，不伪造能力，也不要因此停在方案阶段。
